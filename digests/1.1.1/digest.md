## TL;DR
- Вложения живут на диске (`workspace/attachments/`), а не в теле хода: upload / list / delete + листинг в `<working_context>`.
- При создании сессии заводятся `artifacts/`, `attachments/` и `notes/decisions.md`.
- UI и REPL (`/attach`) умеют класть файлы в ту же папку.
- Это последний крупный «общий» релиз до развилки: LUNA 0.1.1 взял вложения и выкинул `pointer`.

## Нововведения (по продукту)
### Вложения рабочей области
- **Что:** `POST`/`GET`/`DELETE /sessions/{id}/workspace/files` — файлы в `workspace/attachments/` (лимит 20 МБ, чекпоинт на загрузке).
- **Зачем:** пользователь даёт агенту исходники файлами, а не ссылками в JSON хода.

### Осведомлённость агента
- **Что:** `AttachmentsContextProvider` каждый вызов модели кладёт полный листинг каталога в `<user_attachments>`.
- **Зачем:** модель видит актуальное состояние, а не журнал «когда-то загрузили».

## Техническая реализация
### ФС как источник истины
- **Как сделано:** из `TurnRequest` убраны `attachments` / модель `Attachment`. Bootstrap создаёт каталоги workspace. Провайдер читает диск сейчас.
- **Ключевые файлы:** `core/app/routes/workspace.py` (+139/-8), `core/agent/middleware/context_inject.py` (+36/-1), `core/agent/bootstrap.py` (+21/-6).
- **Заметки:** чекпоинт на upload — загрузка обратима вместе с остальным workspace.

### UI / REPL

- **Ключевые файлы:** `devfront/static/app.js` (+275/-194), `scripts/agent_repl.py` (+38/-2).
