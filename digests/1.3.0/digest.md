# Дайджест релиза analyzer-agent-service 1.3.0 (2026-08-17)

> Источник: `C:\dev\analyzer-agent-service`, диапазон `v1.2.4..v1.3.0`.
> Разведывательный обзор родительского проекта. LUNA — независимый проект:
> ничего отсюда не переносится автоматически, это материал для решения.

## TL;DR
- Профиль сессии — каталог на диске (`procedures/profiles/<name>/`: `agent.md`, навыки, субагенты), копия кладётся в `<session>/procedures/`.
- Пул тулов фильтруется тегами `@agent_tool(tags=...)`; тул без тегов — общий фонд.
- `run_script` исполняет скрипт навыка по именам `skill`/`script` (JSON stdin/stdout), без произвольного пути.
- Auth сломали: глобальный пароль снят, `AUTH_ADMIN_PASSWORD` обязателен, старые `cait`/`standalone` больше не принимаются.

## Нововведения (по продукту)
### Реестр профилей
- **Что:** `admin`, `cait_techprocess_profile`, `cait_workpiece_profile`. `GET /profiles` отдаёт `{name, description, requires_admin}`. `POST /sessions` без профиля — 422, неизвестный id — 400.
- **Зачем:** один сервер обслуживает разные рабочие места (полный доступ / техпроцесс / заготовка).

### `run_script`
- **Что:** клиентский профиль запускает заготовленный скрипт навыка в sandbox, не пишет код сам.
- **Зачем:** разделить «исполнить расчёт» и «дать модели оболочку».

### UI
- **Что:** выбор профиля при создании сессии; сессии `admin` — только с токеном.
- **Зачем:** оператор видит, в каком режиме работает агент.

## Техническая реализация
### ProfileRegistry
- **Как сделано:** сканирует `profiles/*/agent.md`, читает YAML-frontmatter (`description`, `requires_admin`). При создании сессии дерево профиля копируется в session procedures. Системный промпт — только этот `agent.md`.
- **Ключевые файлы:** `core/agent/profiles.py` (+109), `core/agent/bootstrap.py` (+86/-71), `core/procedures/profiles/**`.
- **Заметки:** специализация снова «промпт + файлы», не новый класс агента. Это бьётся с архитектурой LUNA лучше, чем `cait`/`standalone` из 1.1.0. Содержание профилей — заводское.

### Теги тулов
- **Как сделано:** `@agent_tool(tags=...)` ограничивает видимость перечисленными профилями. Тег, которого нет в реестре, роняет старт процесса.
- **Ключевые файлы:** `core/agent/tools/__init__.py` (+30/-73), `tests/agent/test_tool_pool.py` (+235/-16).
- **Заметки:** в LUNA уже есть вычитание по `feature` / `main_only` / `fs_scope`. Теги профилей — ещё одна ось. Имеет смысл, только если появятся сами профили.

### run_script
- **Как сделано:** имя навыка/скрипта — идентификатор (`[A-Za-z0-9_-]+`), резолв `<procedures>/skills/<skill>/scripts/<script>.py`. Payload JSON на stdin, ожидание JSON на stdout, timeout 60s, `SandboxExec`. Ошибка перечисляет доступные имена (self-correction). Субагент передаёт путь своей зоны, не main workspace.
- **Ключевые файлы:** `core/agent/tools/run_script_tool.py` (+173), `core/agent/sandbox/exec.py` (+37/-5).
- **Заметки:** идея «скрипт навыка по имени» отделяется от Linux-sandbox. На Windows можно гонять `sys.executable` в workspace без nftables.

### Auth 1.3.0
- **Как сделано:** `AuthGateMiddleware` и `/login` удалены. Аноним ок везде, кроме профилей `requires_admin`. `AUTH_ADMIN_PASSWORD` обязателен (пустой — отказ старта). WS админ-сессии закрывается кодом 4401 до `accept()`.
- **Ключевые файлы:** `core/app/auth.py` (+44/-94), `core/app/routes/sessions.py` (+108/-20).

## Кандидаты на перенос в LUNA
| Идея | Ценность для LUNA | Сложность | Совместимо с LUNA | Заметка |
|------|-------------------|-----------|-----------------|---------|
| Профили как каталоги на ФС | высокая | средняя | да | «Личный ассистент / исследователь / редактор JSON» без домена. Копия в сессию сохраняет filesystem-first. Не тащить CAIT-профили как есть. |
| `@agent_tool(tags=...)` | средняя | средняя | частично | Нужен только вместе с профилями. Иначе раздует `assemble_pool` без выгоды. |
| `run_script` по имени навыка | средняя | средняя | частично | Полезно, если появятся skills со скриптами. Исполнитель — не Linux sandbox, а локальный subprocess. |
| Выбор профиля в UI | средняя | низкая | да | Следствие профилей, не отдельная фича. |

## Что НЕ тянем
- **Содержание профилей ЦАИТ / заготовка и skill `analog-workpiece-report`** — домен.
- **Обязательный `AUTH_ADMIN_PASSWORD` и отказ глобального no-op auth** — LUNA однопользовательский; лучше опциональный пароль из 1.2.4.
- **Ломающий контракт `cait`/`standalone`** — этих профилей в LUNA и не было.
- **Зависимость `run_script` от uid/nftables** — переносить контракт тула, не `SandboxExec` родителя.
