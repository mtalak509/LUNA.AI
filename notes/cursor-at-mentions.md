# Cursor `@`-mentions: как устроен механизм

Заметка по устройству `@` в Cursor (чат Agent), по официальным докам и наблюдаемому
поведению. Это **не** часть LUNA — справочник, если понадобится похожий UX
(явный аттач файла в контекст хода).

Дата: 2026-07-30.

---

## Короткий вердикт

`@` — это **ручной инжектор контекста** на стороне клиента Cursor.

- **Picker** — свойство UI: автокомплит и выбор артефакта.
- **Клиент** после выбора **прикрепляет** материал к payload хода.
- **Ядро / модель** picker’а не содержит: получает уже готовый attached context.

`@file` ≠ «передай модели путь, пусть сама откроет».  
`@file` = «включи содержимое (или снимок) в conversation context этого хода».

---

## Слои

```
пользователь печатает @
        ↓
UI picker (фильтр, выбор файла / папки / docs / …)
        ↓
клиент Cursor резолвит выбор → аттачит в payload
        ↓
запрос к модели: текст сообщения + attached context
        ↓
модель видит материал в окне контекста
        ↓
(опционально) агент ещё читает файлы через tools (lazy)
```

| Слой | Ответственность |
|------|-----------------|
| **UI picker** | Резолв ввода в конкретный артефакт (путь, diff, terminal…) |
| **Клиент IDE** | Сериализация аттача в контекст хода, учёт ignore-правил |
| **Ядро / LLM** | Получает уже включённый контекст; tools — отдельный канал |

Picker **не** зашит в ядро.

---

## Что можно упомянуть

По текущим официальным докам Cursor:

| Mention | Что аттачится |
|---------|----------------|
| Files & Folders | Файл или папка (у папки после выбора можно углубиться через `/`) |
| Docs | Индексированная документация (встроенная + свои через Add new doc) |
| Terminals | Вывод терминала |
| Past Chats | Контекст прошлого чата |
| Git | Diff рабочей копии или ветки относительно main |
| Browser | Контекст встроенного браузера |

Имена вроде `@Code` / `@Codebase` встречались в старых UI и сторонних гайдах;
актуальная documented-поверхность — таблица выше.

---

## Eager vs lazy

| Механизм | Поведение |
|----------|-----------|
| **`@` mention** | Eager: материал кладётся в контекст **сразу**, до ответа модели |
| **Agent tools** (Read, Grep, Glob…) | Lazy: модель сама решает, что открыть по ходу хода |
| **Путь текстом без `@`** | Не гарантирует включение файла в промпт |
| **Rules / skills / MCP** | Другие срезы бюджета контекста, не через picker |

Когда файл уже известен — `@` полезен (фокус + меньше поиска).  
Когда нет — `@` можно не трогать: агент найдёт через tools.

---

## Бюджет контекста

- У чата фиксированное окно под выбранную модель.
- Аттачи `@` живут в срезе **conversation** (вместе с сообщениями и tool results),
  не в отдельном невидимом канале.
- Кольцо контекста у инпута показывает заполненность; по клику — разбивка
  (system, tools, rules, skills, MCP, subagents, summary, conversation…).
- Большие аттачи съедают токены: меньше места под историю и tool results → раньше
  срабатывает суммаризация старых ходов.
- Файлы из `.cursorignore` через `@` недоступны (как и через обычный file access агента).

Точный wire-format (теги, truncation огромных файлов, «папка = все файлы или только
дерево») Cursor публично не документирует.

---

## Режимы

`@` один и тот же в Agent / Ask / Plan / Debug. Меняются права (писать / только читать),
не механизм аттача. Смена режима — отдельное окно контекста.

---

## Практический takeaway для дизайна похожего механизма (напр. в LUNA)

Минимальная модель, если копировать идею, а не UI Cursor:

1. **Surface (CLI / web)** — picker или команда резолвит путь.
2. **Session API** — принимает конкретный путь/артефакт и кладёт его в зону
   вложений / в envelope хода (не «магическую строку `@…`» для LLM).
3. **Agent core** — видит либо listing + путь (как сейчас `workspace/attachments/`),
   либо уже вложенное содержимое; дальше сам читает tools’ами при необходимости.

Разделять: **резолв в UI** и **явный аттач в сессию**. Не тащить autocomplete в ядро агента.

Связанные места в LUNA сегодня: `workspace/attachments/`, CLI `/attach`,
HTTP `POST /sessions/{id}/attachments`, listing в context inject.
