# Продуктовый меморандум LUNA

## Направление

LUNA — компактная платформа для создания и эксплуатации корпоративных AI-агентов внутри
контролируемого компанией контура. Её основа — понятный агентный цикл, локальное развёртывание,
сменные модели, файловое состояние и код, который способен понять и расширить один инженер.

LUNA не стремится стать универсальным бизнес-приложением. Бизнес-процессы реализуются поверх
стабильного ядра через процедуры, инструменты, MCP-серверы и специализированные интеграции.

## Продуктовая линейка

### LUNA Core

LUNA Core — открытая основа для разработчиков:

- агентный runtime и middleware;
- контекст, сжатие истории и файловые рабочие зоны;
- файловые инструменты, checkpoints и human-in-the-loop;
- поддержка моделей и API расширений;
- делегирование и базовое подключение MCP;
- локальный CLI как полноценный однопользовательский интерфейс.

Core должен оставаться полезным самостоятельно: разработчик может установить его, подключить
модель, собрать агента и работать локально без коммерческого продукта.

### LUNA Enterprise

LUNA Enterprise — коммерческая система для эксплуатации Core внутри организации:

- многопользовательский сервер и HTTP API;
- web-интерфейс Workspace;
- постоянные сессии, владельцы, организации и квоты;
- аутентификация через OIDC/Keycloak и ролевой доступ;
- аудит и централизованные политики агентов;
- секреты и управляемые MCP-подключения;
- профили агентов, администрирование, наблюдаемость, резервное копирование и поддерживаемое
  развёртывание.

Компания платит не за доступ к агентному циклу, а за его контролируемую и надёжную эксплуатацию.

## Границы

CLI относится к Core. Workspace относится к Enterprise, но остаётся клиентом сервера, поэтому
компания может заменить его собственным интерфейсом.

Протокол и MCP-клиент относятся к Core. Enterprise добавляет каталог подключений, credentials,
политики доступа, аудит и поддерживаемые корпоративные интеграции.

Текущие FastAPI-сервер и web UI — reference implementation, но ещё не enterprise-продукт. В них
нет аутентификации, владельцев, постоянных серверных сессий, аудита, секретов и эксплуатационного
контроля.

## Правило roadmap

Развитие Core должно упрощать понимание, расширение и локальный запуск агентов. Развитие
Enterprise должно делать их безопасными, управляемыми и пригодными для эксплуатации в компании.

Функция не попадает в roadmap только потому, что она появилась в родительском проекте: она
должна усиливать одну из этих двух целей.
